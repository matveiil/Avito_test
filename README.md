# Avito

Решение задачи ранжирования объявлений (Information Retrieval) для платформы Авито. 
Итоговый скор на платформе: **Recall@50 = 0.630196**.

## Структура репозитория
* `data/` — директория для хранения исходных датасетов (`benchmark_items.parquet`, `benchmark_queries.parquet`).
* `baseline.py` — основной скрипт решения, генерирующий финальный ответ.
* `validate.py` — локальный валидатор формата файла ответов.
* `answer.csv` — файл с предсказаниями, сгенерированный скриптом.

## Подход к решению
Из-за огромного пространства поиска (2 452 запроса × 189 212 объявлений) применение тяжелых ML-моделей напрямую ко всем парам вычислительно нецелесообразно. Решение построено на оптимизированном бейзлайне с использованием методов классического лексического поиска (TF-IDF) и бизнес-эвристик.

### 1. Подготовка текстовых признаков и балансировка весов
Для построения лексического индекса использовалась склейка полей объявлений. В ходе анализа (EDA) было выявлено, что длинные значения в `item_description_raw` сильно размывают вес ключевых слов. 
* **Дублирование заголовка:** Чтобы сместить фокус алгоритма на самую важную часть объявления, поле `item_title_raw` дублировалось дважды при склейке текста. 
* **Обрезка описания:** Описание `item_description_raw` урезалось до первых 150 символов.
* **Тексты запроса:** Использовалась склейка `search_query` и `search_infm_params_text`.
* Все тексты приводились к нижнему регистру с удалением спецсимволов.

### 2. Лексический поиск (TF-IDF)
Векторизация текстов проводилась с помощью `TfidfVectorizer`:
* Учитывались униграммы и биграммы (`ngram_range=(1, 2)`).
* Применен параметр `sublinear_tf=True` (логарифмическое сглаживание частоты) для защиты от текстового спама со стороны продавцов, многократно повторяющих одно слово.
* Скоринг производился через матричное умножение (Dot Product) векторов запросов и корпуса.

### 3. Бизнес-эвристики и тай-брейкеры
Так как Recall@50 не требует идеальной сортировки внутри топ-50, главной задачей было вытолкнуть релевантные объявления в пул кандидатов. Базовый TF-IDF скор корректировался с помощью следующих признаков:
1. **Географический фильтр (+1.0 к скору):** Бинарный признак совпадения локации (`search_location_id == item_location_id`). Услуги и товары обладают сильной локальной привязкой. Жесткий буст гарантировал приоритет местным объявлениям.
2. **Совпадение категорий (+0.05 к скору):** Совпадение `search_category` и `item_category_id` использовалось как мягкий тай-брейкер. Это позволило ранжировать выше товары нужной категории при равном текстовом совпадении, не ломая общую логику поиска.
3. **Качество объявления (макс. +0.02 к скору):** Использовались нормализованные значения `item_rating` и логарифм количества отзывов `item_rating_reviews_count`. Это давало микро-преимущество проверенным продавцам.

## Локальная проверка качества
Перед каждой отправкой на платформу сгенерированный файл `answer.csv` проходил жесткую проверку через скрипт `validate.py`. 
Скрипт проверял типичные ошибки, которые могли привести к невидимой просадке метрики на платформе:
* Потерю ведущих нулей и приведение hex-хэшей к типу float Pandas-ом.
* Наличие ровно 50 уникальных кандидатов на каждый запрос.
* Длину каждого `item_id` (ровно 16 символов).
* Проверку существования каждого `item_id` в исходном корпусе `benchmark_items.parquet`.

## Инструкция по запуску
1. Поместите файлы `benchmark_items.parquet` и `benchmark_queries.parquet` в папку `data/`.
2. Установите зависимости: `pip install pandas numpy scikit-learn pyarrow`.
3. Запустите скрипт генерации: `python baseline.py`. Скрипт отработает за 1-2 минуты и сохранит `answer.csv`.
4. Запустите проверку формата: `python validate.py`.
